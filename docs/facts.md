# 事实管理

## 用途

事实是识别时已知的条件，例如车辆数量为 8、动力编组为 4M4T、运营速度为 350 km/h。
规则描述多个条件满足时可以得到的候选结论；事实本身不包含 IF 条件组合或 THEN 结论。

当前事实管理是按知识库保存、复用的事实条目库，不是车型参数档案，也不是一次实验的完整输入。
因此同一字段可以保存多个不同的值，例如 8 辆和 16 辆，推理工作台由用户选择本次已知事实。
不能将事实库中的全部条目直接合并成一次实验，未知的特征也不能默认填入或当作否定条件。
在推理工作台选择事实并点击“运行推理”；保存事实不会自动运行规则。

## 操作

进入“事实管理”，选择知识库后新建事实。选择特征字段并填写值即可保存。
事实名称可选，留空时自动生成；可选填资料链接和备注。
支持按名称、特征字段和值搜索，也支持按字段筛选及分页。
列表的“编辑”和“删除”操作针对单条事实；展开行可查看来源和备注。
旧版仅有名称的事实会显示“待补充”，编辑并补充字段和值后即可作为结构化条目使用。

## 数据约定

- 与规则编辑共用字段定义，三种速度独立存储，单位为 km/h。
- 数值保留为 JSON 数字，文本保留为 JSON 字符串，不将字符串“350”默认为数字。
- 数值范围 0–1000；车辆数量必须为正整数。
- 文本值不能为空，最长 200 字；名称最长 80 字，备注最长 1000 字。
- 一个知识库内不允许重复名称或重复的字段和值；不同知识库相互隔离。
- 来源地址只接受 HTTP 和 HTTPS；所有 SQL 写入使用参数绑定。
- 数据库升级至版本 5，保留旧事实编号和名称，旧记录缺少的字段和值保持为空。
- 删除事实不会改动规则：当前规则引用共享字段和值，没有通过事实编号绑定条目。

## 接口

```text
GET    /api/knowledge-bases/:baseId/facts
POST   /api/knowledge-bases/:baseId/facts
GET    /api/knowledge-bases/:baseId/facts/:factId
PUT    /api/knowledge-bases/:baseId/facts/:factId
DELETE /api/knowledge-bases/:baseId/facts/:factId
```

POST 和 PUT 使用完整对象：

```json
{
  "name": "八辆编组",
  "field_key": "car_count",
  "value": 8,
  "source_url": "",
  "notes": ""
}
```

输入不合法返回 400，不存在或不属于当前知识库的条目返回 404，重复事实返回 409。
删除成功返回 204。查询结果包含创建和更新时间，数据库持久化后刷新仍可读取。
