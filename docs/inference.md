# 推理与实验记录

在“推理工作台”选择知识库，通过逐题问答输入观察到的列车特征。
问题由大众化到专业排列：品牌、外观、车辆数量、用途、适用环境、系列、
车型状态、动力形式、运营速度、动力编组、设计速度、最高实验速度。
每题列出当前知识库该字段的全部有效事实值，不按前面的答案删减选项。
没有可用事实的字段不生成空题，已推导特征不作为观察问题。
当前铁路知识库有 10 题；日后补入外观和用途事实后自动出现对应问题。

品牌、速度等字段单选，外观和环境多选。每题均提供“我不知道”，点击即清除该题答案并跳到下一题。
跳过不产生事实，也不等价于“不符合”。可以返回上一题或在回答确认中修改。
全部跳过时显示暂无识别结果，不提交空事实实验。
完成后确认回答并点击“查看识别结果”，只有已知答案对应的事实编号会提交给推理接口。
每次最多提交 100 项，旧版缺少字段和值的事实不可参与。

## 算法

正向推理按优先级降序、规则编号升序评估已启用且通过校验的规则。
AND 需要所有条件满足，OR 需要任一条件满足。
条件保留满足、冲突、未知三种状态：没有输入的字段不满足“不等于”。
新结论加入 `derived_feature`，通过字段依赖索引重新调度相关规则。
规则每次实验最多触发一次、相同结论只加入一次，因此循环规则能够终止。

候选车型筛选独立核对每条已输入事实，包括规则条件、车型系列和来源参数。
出现明确冲突的车型排除；至少一项匹配才展示。
全部输入均有资料支持时标记“已知条件符合”；仍有未知项时标记“待核验”。
这不代表完整规则命中或唯一识别，界面另列“完整规则”状态，不生成概率。
环境资料是正向特征集合：已知抗风沙不能据此否定高寒。

“推理过程”同时展示候选筛选和实际规则触发。逐条输入核对车型，记录该步排除、
保留和资料不足的车型；缺失资料只保留为未知，不以此排除车型。
候选依据显示每条输入的核验情况，并可展开完整规则查看满足和未知的条件。
候选需要至少一项已核实输入；逐步筛选阶段保留的全部未知车型不一定进入最终候选。
完整规则尚未命中也能查看筛选过程；只有真正触发的规则才进入规则触发记录。
历史记录缺少筛选过程时，使用其已保存的规则和事实快照生成，不采用当前修改后的规则。

## 历史与文件

实验保存事实、规则、来源、推理过程和候选核验快照。
后续编辑或删除事实、规则不会改变已保存的实验。
在实验记录查看详情，可导出 JSON 或 Markdown。
导出时后端实际写入 `data/reports/knowledge-base-ID/run-ID.ext` 并提供下载。
删除实验记录不删除已经导出的本地文件。

```text
GET    /api/knowledge-bases/:baseId/runs
POST   /api/knowledge-bases/:baseId/runs
GET    /api/knowledge-bases/:baseId/runs/:runId
DELETE /api/knowledge-bases/:baseId/runs/:runId
GET    /api/knowledge-bases/:baseId/runs/:runId/report?format=json
GET    /api/knowledge-bases/:baseId/runs/:runId/report?format=md
```

POST 内容为 `{ "fact_ids": [2, 4] }`。
重复编号、标量冲突、缺少字段值返回 400，跨知识库或不存在的事实返回 404。
数据库版本 5 为历史记录增加规则快照。
